- Site access is gated by Google sign-in in AuthGate, with the allowed email domain enforced by a backend trigger on new accounts; why: the client check is UX only, the trigger is the real guard.
- A migration file already committed under drizzle/migrations but not yet applied must be applied by running its SQL verbatim and then inserting the matching row into drizzle.__drizzle_migrations (hash = sha256 of the file bytes, created_at = that journal entry's `when`); why: the database migration tool always authors its own copy of the SQL, so the committed file and the copy both run and the second CREATE TABLE collides, rolling everything back.
