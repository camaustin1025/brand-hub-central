- Before starting new work, fetch `origin/codex/single-page-brand-hub` and check the published commit at `https://grooveguide.lovable.app` (the HTML `data-commit-sha` marker). Compare both with the local branch, HEAD, and working-tree changes. Start from the latest live release; if the remote branch is ahead of live, identify those unpublished changes before choosing a base. Preserve local edits and untracked drafts before switching or fast-forwarding, never overwrite them or restore an old stash wholesale. If the live version cannot be verified, say so before editing. Repeat this check before publishing; why: an older local branch previously produced a misleading preview and could have reverted newer live content.
- Site access is gated by Google sign-in in AuthGate, with the allowed email domain enforced by a backend trigger on new accounts; why: the client check is UX only, the trigger is the real guard.
- A migration file already committed under drizzle/migrations but not yet applied must be applied by running its SQL verbatim and then inserting the matching row into drizzle.__drizzle_migrations (hash = sha256 of the file bytes, created_at = that journal entry's `when`); why: the database migration tool always authors its own copy of the SQL, so the committed file and the copy both run and the second CREATE TABLE collides, rolling everything back.
- Guest (non-Ordergroove) access is invite-only: admins manage `guest_invites` through the `guest-admin` edge function, the domain trigger also accepts active invites, and AuthGate reads `my_access()` on every session load; why: expiry/revocation must be checked server-side, not only at sign-up.
